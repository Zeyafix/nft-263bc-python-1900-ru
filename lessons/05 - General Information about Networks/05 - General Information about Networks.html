02 / Зачем компьютерам сеть

Представьте, что нужно передать одногруппнику файл. Можно скопировать его на флешку и отнести лично. Сеть позволяет передать данные между устройствами по линии связи: вы отправляете файл, а другое устройство принимает его.

Определение

Компьютерная сеть

Компьютерная сеть объединяет устройства, которые могут обмениваться данными. Участниками бывают компьютеры, телефоны, принтеры, серверы и другие устройства.

  • Сообщения. Вы пишете в учебный чат, и текст поступает другим участникам.
  • Файлы. Вы отправляете архив с домашним заданием в MyStat.
  • Общие ресурсы. Несколько компьютеров пользуются сетевым принтером или общей папкой. Принтеру не обязательно быть подключённым USB-кабелем к каждому ПК.
Масштаб сети
НазваниеЧто объединяетПример
LAN (Local Area Network)Устройства в пределах небольшой территорииДомашний ноутбук, телефон и принтер; компьютеры учебного класса
WAN (Wide Area Network)Сети на больших расстоянияхСоединение офисных сетей в разных городах через провайдера

Интернет объединяет множество взаимосвязанных сетей по всему миру. Интернет-провайдер, или ISP (Internet Service Provider), подключает вашу сеть к другим сетям. Когда вы открываете зарубежный сайт, данные проходят через несколько сетей.

Локальная сеть может работать без интернета. Например, два компьютера в классе могут обменяться файлом внутри LAN, даже если связь учебного центра с провайдером прервалась. Для этого обмен файлами должен быть настроен на самих компьютерах.

03 / Как устройства соединяются

Для обмена данными нужна среда передачи. В домашней сети это обычно кабель или радиосвязь. По кабелю Ethernet передаются сигналы между сетевыми портами. Wi-Fi передаёт данные по радио, поэтому кабель до ноутбука или телефона не требуется.

Способы подключения и сетевые устройства
ЭлементДля чего нуженПример
EthernetПроводное подключение к сетиКабель от ПК к LAN-порту домашнего роутера
Wi-FiБеспроводное подключение к локальной сетиТелефон подключается к домашней сети по её имени
Точка доступаПодключает Wi-Fi-устройства к локальной сетиПередаёт данные между телефоном и остальной домашней сетью
Коммутатор (switch)Соединяет устройства внутри локальной сети и передаёт кадры на нужные портыОбъединяет проводные компьютеры класса
Маршрутизатор (router, роутер)Пересылает IP-пакеты между сетямиСвязывает домашнюю LAN с сетью провайдера

Один домашний «Wi-Fi-роутер» часто совмещает маршрутизатор, коммутатор для LAN-портов и точку доступа. Поэтому компьютер по кабелю и телефон по Wi-Fi могут оказаться в одной локальной сети. Это разные способы подключения к одной сети.

Обратите внимание

Wi-Fi подключён, а сайт не открывается

Значок Wi-Fi говорит о соединении с точкой доступа. Он не гарантирует, что роутер имеет рабочую связь с провайдером или что нужный сервер доступен. Например, кабель провайдера отключён, а домашняя точка доступа продолжает работать.

  1. Проверьте, подключено ли устройство к нужной сети.
  2. Откройте другой известный сайт. Если он работает, проблема может относиться только к первому сайту.
  3. Проверьте доступ в интернет с другого устройства в той же сети. Если не работает нигде, возможна общая проблема роутера или провайдера.

Эти наблюдения помогают описать проблему: «Wi-Fi подключён, но несколько сайтов не открываются на двух устройствах». Это полезнее, чем просто «интернет сломался». Одного такого наблюдения ещё недостаточно для точного диагноза.

04 / Адреса устройств: IP и MAC

В сети одновременно общаются разные устройства. Чтобы данные дошли до нужного получателя, используются адреса. У IP и MAC разные задачи: первый помогает доставлять пакеты по сетям, второй участвует в доставке по текущему локальному соединению.

Определение

IP-адрес

IP-адрес назначается сетевому интерфейсу, например Wi-Fi-адаптеру ноутбука. Он используется для обмена IP-пакетами внутри сети и между сетями. У компьютера с несколькими интерфейсами может быть несколько IP-адресов.

В примерах используем IPv4: четыре числа от 0 до 255, разделённые точками, например 192.168.1.10. Существует и IPv6, у которого другая запись, например 2001:db8::10. В выводе команд можно встретить оба вида.

Определение

MAC-адрес

В Ethernet и Wi-Fi MAC-адрес используется для доставки кадров по локальному соединению. Кадр можно представить как местную «оболочку» для IP-пакета. Пример MAC-адреса: 02:11:22:33:44:10. В Windows разделителем часто служит дефис.

Когда получатель находится в другой сети, компьютер отправляет кадр своему шлюзу, обычно домашнему роутеру. В этой локальной передаче нужен MAC шлюза. Затем роутер передаёт пакет дальше в новой оболочке. MAC вашего ноутбука не путешествует через весь интернет до сайта. MAC также может меняться, например при использовании случайных адресов Wi-Fi.

Частные и публичные IPv4-адреса
ВидНазначениеЧто важно помнить
Private IP, частный адресАдрес внутри частной сети, например 192.168.1.10Не маршрутизируется напрямую в публичном интернете; может повторяться в разных частных сетях
Public IP, публичный адресАдрес для маршрутизации в интернетеВнешняя сторона соединения; сам по себе не означает, что устройство разрешает входящие подключения

Частные диапазоны IPv4: 10.0.0.0–10.255.255.255, 172.16.0.0–172.31.255.255 и 192.168.0.0–192.168.255.255. Например, адрес 172.66.168.111 из схемы ниже не входит в частный диапазон 172.16–172.31.

У домашнего роутера есть сторона LAN и сторона WAN. В обычной домашней сети с NAT роутер заменяет частный адрес отправителя на внешний адрес и запоминает соединение, включая номера портов. Порт помогает различать сетевые соединения программ. По этой записи роутер понимает, какому устройству передать ответ. Поэтому внешний сервер обычно видит общий публичный IP выхода в интернет.

Иногда дополнительное преобразование адресов выполняет провайдер (CGNAT), и публичный адрес принадлежит его оборудованию. При VPN видимым адресом может быть адрес VPN-сервера. В дальнейших простых схемах считаем, что public IP находится прямо на домашнем роутере.

Команды показывают настройки, но не меняют их. Ваши значения могут отличаться от учебного примера. При обычном домашнем NAT ipconfig показывает частный адрес компьютера, а не публичный адрес роутера.

05 / Доменные имена и DNS

Запомнить mystat.itstep.org проще, чем набор чисел. Такое имя называется доменным. DNS (Domain Name System) помогает по имени получить адреса, которые программы используют для соединения. Имена также позволяют менять адреса серверов, сохраняя привычный адрес сервиса для людей.

  1. Вы указываете имя mystat.itstep.org.
  2. Если подходящего ответа ещё нет в кэше, система обращается к DNS. Кэш хранит недавно полученные ответы некоторое время.
  3. DNS возвращает сведения об адресах. У имени может быть несколько IPv4- и IPv6-адресов.
  4. Программа использует подходящий адрес для подключения к сервису. DNS не передаёт саму веб-страницу.
Запрос к DNS в терминале 
nslookup mystat.itstep.org

Выполните эту команду в PowerShell. В начале вывода обычно указаны DNS-сервер и его адрес: это тот, кого вы спросили. Ниже находятся имя и адреса запрошенного узла. Они могут отличаться у разных пользователей и меняться со временем.

06 / Клиент, сервер и передача данных

Определение

Запрос и ответ

Клиент обращается за данными или действием. Сервер принимает запрос, обрабатывает его и отправляет ответ. Например, браузер запрашивает список домашних заданий, а сервер MyStat возвращает данные для его показа.

Это роли программ. Словом «сервер» также называют компьютер, на котором запущена серверная программа. Однако серверная программа может работать и на обычном ноутбуке. Один компьютер способен одновременно запускать браузер-клиент и сервер для другого приложения.

  1. Клиент: «Покажи список файлов в моей папке».
  2. Сервер проверяет, кто обратился и есть ли у него доступ, затем получает список файлов.
  3. Сервер отправляет ответ. Это могут быть данные или сообщение об ошибке, например об отсутствии доступа.
  4. Клиент обрабатывает ответ и показывает результат пользователю.

Большой файл не проходит по сети одним неделимым куском. Данные передаются частями в пакетах. Пакеты содержат данные и служебную информацию, в том числе IP-адреса. Маршрутизаторы пересылают их к следующему участку пути.

Пакеты могут задерживаться, теряться или приходить в другом порядке. Для надёжной передачи сетевые протоколы, например TCP, обеспечивают упорядочивание и повторную передачу потерянных данных. Поэтому картинка может появиться с задержкой, хотя часть её данных уже пришла.

Подсказка

Представьте отправку книги по частям

Вы разложили главы по пронумерованным конвертам. Каждый конверт содержит адрес, а получатель собирает главы в нужном порядке. Это аналогия: в настоящей сети данные делятся на байты, а правила доставки задают протоколы. Пакет не равен целому сообщению чата или целому файлу.

07 / Примеры путей сообщения

На схемах синим показаны домашние устройства, оранжевым промежуточные маршрутизаторы, ISP обозначает провайдера. Линия показывает возможное соединение.

  1. PC слева имеет private IP 192.168.1.10 и MAC 02:11:22:33:44:10. Для обращения к внешнему сервису он отправляет пакет через шлюз 192.168.1.1, то есть домашний Wi-Fi router.
  2. Домашний роутер запоминает исходящее соединение и при NAT заменяет адрес отправителя своим WAN-адресом 198.51.100.10. Поэтому частный адрес PC не используется для обратной маршрутизации через интернет.
  3. Один из возможных путей на рисунке: Wi-Fi router → R1 → R2 → ISP → R5 → R6 → server router. Каждый маршрутизатор выбирает следующий участок пути.
  4. На WAN-стороне server router указан 172.66.168.111, а сервер внутри его LAN имеет адрес 10.20.0.11. Для этой схемы предполагаем, что роутер сервера настроен принимать обращения к сервису и направлять их на внутренний сервер.
  5. Серверная программа обрабатывает запрос. Если ей нужны данные с показанных справа хранилищ, она обращается к ним через коммутатор. Браузер клиента не обязан обращаться к этим хранилищам напрямую.
  6. Ответ проходит через server router и интернет к домашнему роутеру. Домашний роутер находит запись соединения, восстанавливает адрес PC 192.168.1.10 и передаёт данные ему по локальной сети.

Для иллюстрации ответ может пройти так: server → server router → R6 → R5 → ISP → R2 → R1 → Wi-Fi router → PC. Совпадение прямого и обратного маршрутов не обязательно. При доставке внутри домашней Ethernet/Wi-Fi-сети используется MAC нужного интерфейса; внешний сервер не получает MAC клиента как адрес доставки через интернет.

Рассмотрим ещё один пример.

Оба PC имеют адрес 192.168.1.10. Конфликта нет: это разные локальные сети. Несмотря на это левый PC не может указать на правый PC через публичный интернет, используя private IP. Взаимодействовать они могут через роутеры, у которых есть внешние адреса: слева 198.51.100.10, справа 174.23.202.10.

Условие примера

Что нужно для связи PC с PC

P2P (peer-to-peer) означает, что программы на устройствах обмениваются данными как равноправные участники. Но линия на рисунке ещё не создаёт доступ к программе. При NAT нужны согласование соединения приложениями или специальная настройка; иногда используется промежуточный сервер. Также должны разрешать соединение межсетевые экраны. Считаем, что приложение уже установило доступный канал между PC.

  1. Программа на левом PC готовит данные для другого участника. В своей LAN компьютер передаёт их домашнему роутеру.
  2. Один из путей по рисунку: левый Wi-Fi router → R1 → R3 → R2 → R5 → ISP → R11 → R13 → R17 → правый Wi-Fi router.
  3. Правый роутер использует согласованное соединение или настроенное правило, чтобы направить данные на правый PC с private IP 192.168.1.10. В своей LAN он использует локальный адрес нужного интерфейса для последней доставки.
  4. Правый PC отвечает через свой роутер. Например, ответ проходит правый Wi-Fi router → R17 → R13 → R11 → ISP → R5 → R2 → R3 → R1 → левый Wi-Fi router → левый PC.

Для понимания маршрута достаточно различать private IP, внешний IP и локальный MAC.

В клиент-серверной модели роли запроса и обслуживания обычно разделены. В P2P участник может и запрашивать, и отдавать данные. В обоих случаях интернет передаёт пакеты через сетевое оборудование.
