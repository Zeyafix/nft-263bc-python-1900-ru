01 / Как программа выбирает действия

До этого мы записывали команды, которые выполнялись одна за другой: получить данные, посчитать результат, вывести его. Теперь научимся менять действия программы в зависимости от данных. Например, касса может добавить подарок к большой покупке и применить скидку к дорогой.

Определение

Последовательность и ветвление

Последовательное выполнение означает, что программа выполняет команды сверху вниз, одну за другой. Ветвление позволяет выполнить или пропустить блок команд в зависимости от условия.

В предыдущем уроке сравнения и логические операторы помогали получить True или False. Теперь этот результат будет определять, какие команды запустятся.

Представим простую кассу: покупатель указывает цену одной единицы товара и количество, касса умножает их и сообщает сумму. Сначала опишем алгоритм на псевдокоде. Это запись шагов без строгого синтаксиса Python; запускать её в Python не нужно. В этой записи READ означает «получить ввод», SET означает «задать значение», а PRINT означает «показать».

Псевдокод: обычная покупка 
READ price
READ quantity
SET total_price TO price * quantity
PRINT total_price
PRINT quantity

При цене 400 и количестве 20 получится 8000 к оплате и 20 единиц товара. При других числах изменится результат вычисления, но набор выполняемых шагов останется тем же.

Добавим два независимых правила: при покупке от 10 единиц включительно выдаём ещё 3 бесплатно; при сумме от 200 включительно уменьшаем оплату на 5%. Запись IF означает «если», а END IF отмечает конец условного блока в этом псевдокоде.

Псевдокод: подарок и скидка 
READ price
READ quantity
SET total_price TO price * quantity
SET quantity_obtained TO quantity

IF quantity >= 10
    SET quantity_obtained TO quantity_obtained + 3
END IF

IF total_price >= 200
    SET total_price TO total_price * 0.95
END IF

PRINT total_price
PRINT quantity_obtained

Здесь уже есть шаги, которые выполнятся только при подходящих данных. Умножение на 0.95 оставляет 95% исходной суммы, то есть уменьшает её на 5%. Для цены 400 и количества 20 покупатель получит 23 единицы и заплатит 7600.

02 / Конструкция if

В Python условный блок начинается со слова if, после которого записывают условие и двоеточие. Если условие истинно, Python выполняет команды с отступом под ним. Если условие ложно, весь этот блок пропускается, а выполнение продолжается после него.

Касса: ввод 400 и 20 
price = int(input("Enter price: "))
quantity = int(input("Enter quantity: "))

total_price = price * quantity
quantity_obtained = quantity
has_obtained_additional = False


if quantity >= 10:
    quantity_obtained += 3
    has_obtained_additional = True

if total_price >= 200:
    total_price *= 0.95


print(f"\nPayment required: {total_price}")

if has_obtained_additional:
    print("You have received an extra item as a gift!")

print(f"Quantity: {quantity_obtained}")
Консоль
Enter price: 400
Enter quantity: 20

Payment required: 7600.0
You have received an extra item as a gift!
Quantity: 23
  1. Сначала total_price получает 400 * 20, то есть 8000, а quantity_obtained получает 20. Переменная has_obtained_additional начинается с False: подарок пока не добавлен.
  2. Проверка quantity >= 10 даёт True. Внутри первого блока выполняются обе команды: количество к выдаче увеличивается до 23, а признак подарка становится True.
  3. Затем независимо проверяется total_price >= 200. Условие истинно, поэтому total_price *= 0.95 заменяет сумму результатом умножения: 7600.0. После умножения на число типа float результат тоже имеет тип float.
  4. Программа выводит сумму. Последовательность \n в начале f-строки создаёт пустую строку перед сообщением.
  5. Условие if has_obtained_additional: проверяет сохранённое логическое значение. Оно равно True, поэтому появляется сообщение о подарке. Последняя команда выводит количество к выдаче: 23.

Переменную, которая хранит ответ «да» или «нет» о состоянии программы, часто называют флагом. Здесь флаг нужен, чтобы после расчётов вспомнить, был ли добавлен подарок. Для логического значения достаточно if has_obtained_additional:; дописывать == True не требуется.

Определение

Двоеточие и отступ задают блок

  • Двоеточие завершает строку с условием и показывает, что дальше идёт блок команд.
  • Четыре пробела в начале строки являются принятым отступом для одного уровня вложенности в Python. Все команды одного блока должны иметь одинаковый отступ. Настройте редактор на пробелы и не смешивайте их с табуляцией.
  • Возврат к прежнему отступу заканчивает блок. В Python нет команды END IF: границы определяются отступами.
  • Пустая строка делает файл удобнее для чтения, но сама по себе не заканчивает блок в Python-файле. В примере границу показывает именно отступ следующей команды.

В этой программе вывод суммы и последняя команда print() стоят без отступа. Они выполняются независимо от результата условий, если выполнение дошло до них без ошибки. А сообщение о подарке стоит внутри if и зависит от флага. Отступы влияют на логику, а не только на внешний вид кода.

Если ввести цену 10 и количество 2, первые два условия будут ложными. Количество останется равным 2, сумма останется целым числом 20, флаг сохранит False, и сообщение о подарке не появится. Ложное условие само по себе не является ошибкой.

03 / Два варианта: if и else

Иногда при ложном условии нужно выполнить другое действие. Для этого после блока if добавляют else: с собственным блоком. Слово else читается как «иначе»: если условие if истинно, выполняется первый блок, иначе выполняется второй. При обычном выполнении выбирается ровно один из них.

У else нет собственного условия, потому что оно уже означает «условие связанного if не выполнилось». После него пишут только двоеточие. Слова if и else стоят на одном уровне отступа, а команды каждой ветки сдвинуты на четыре пробела.

Изменим кассу: теперь флаг подарка будет получать значение в одной из двух веток.

Касса с else: ввод 400 и 5 
price = int(input("Enter price: "))
quantity = int(input("Enter quantity: "))

total_price = price * quantity
quantity_obtained = quantity


if quantity >= 10:
    quantity_obtained += 3
    has_obtained_additional = True
else:
    has_obtained_additional = False

if total_price >= 200:
    total_price *= 0.95


print(f"\nPayment required: {total_price}")

if has_obtained_additional:
    print("You have received an extra item as a gift!")

print(f"Quantity: {quantity_obtained}")
Консоль
Enter price: 400
Enter quantity: 5

Payment required: 1900.0
Quantity: 5
  1. Начальная сумма равна 2000, количество к выдаче равно 5.
  2. Условие 5 >= 10 ложно. Команды внутри первого if пропускаются, а внутри else флаг получает False.
  3. После конструкции if/else выполнение продолжается со следующей независимой проверки. 2000 >= 200 истинно, поэтому сумма уменьшается до 1900.0.
  4. Выводится сумма. Проверка флага ложна, сообщение о подарке пропускается. Количество к выдаче остаётся равным 5.

В первом варианте кассы мы заранее задавали False и меняли его на True при выдаче подарка. Здесь значение задаётся внутри if или внутри else. Оба способа подходят: к моменту проверки флаг получает значение при любом из двух исходов.

Важно

К какой проверке относится else

else продолжает связанную с ним конструкцию if на том же уровне отступа. В приведённой кассе оно относится к проверке количества, поэтому отсутствие подарка не отменяет отдельную проверку скидки.

Между концом блока if и его else нельзя вставить постороннюю команду на уровне самого if. Иначе конструкция уже закончится и у else не будет пары.

04 / Несколько вариантов: elif

Для выбора из нескольких вариантов используют elif, сокращение от «else if», то есть «иначе, если». Python проверяет условия сверху вниз. Как только одно из них оказывается истинным, выполняется его блок, а остальные условия и блоки этой цепочки пропускаются.

Цепочка начинается с одного if, затем может содержать несколько elif и завершаться одним else. У каждого elif есть условие и двоеточие. Последний else необязателен: без него, если все условия ложны, программа просто продолжит выполнение после цепочки.

Определим категорию температуры. Это условные названия для учебного примера.

Температура: одна цепочка elif 
temperature = float(input("Enter temperature: "))

if temperature > 40:
    msg = "extreme heat"
elif temperature > 30:
    msg = "hot"
elif temperature > 20:
    msg = "warm"
elif temperature > 10:
    msg = "moderate"
elif temperature > 0:
    msg = "cool"
elif temperature > -20:
    msg = "cold"
else:
    msg = "extreme cold"

print(msg)
Консоль
Enter temperature: 15
moderate

Проверки 15 > 40, 15 > 30 и 15 > 20 ложны. Проверка 15 > 10 истинна, поэтому msg получает строку "moderate". До проверок temperature > 0 и temperature > -20 выполнение уже не дойдёт, хотя для числа 15 они тоже были бы истинными. После цепочки команда print(msg) выводит выбранную категорию.

А что изменится, если заменить все elif на отдельные if?

Температура: независимые if 
temperature = float(input("Enter temperature: "))

if temperature > 40:
    msg = "extreme heat"
if temperature > 30:
    msg = "hot"
if temperature > 20:
    msg = "warm"
if temperature > 10:
    msg = "moderate"
if temperature > 0:
    msg = "cool"
if temperature > -20:
    msg = "cold"
else:
    msg = "extreme cold"

print(msg)
Консоль
Enter temperature: 15
cold

Теперь каждый if начинает новую проверку. При 15 > 10 переменная msg получает "moderate", затем при 15 > 0 получает "cool", а при 15 > -20 получает "cold". Каждое присваивание заменяет предыдущее значение. Печать стоит в самом конце, поэтому в терминале появляется только последняя строка: cold.

Завершающий else во втором примере относится только к последнему if temperature > -20:. Он не означает «ни одна из всех предыдущих проверок не сработала». При температуре 15 последний if истинный, поэтому этот else пропускается.

Какую конструкцию выбрать
ЗадачаПодходПричина
Добавить подарок и отдельно проверить скидкуНесколько ifОба действия могут понадобиться одновременно.
Сообщить об успехе или отказеif/elseОдин из двух взаимоисключающих исходов.
Назначить одну категорию температурыif/elif/elseНужна одна подходящая категория, без последующей перезаписи.
Важно

Успешный запуск не проверяет все ветки

В непроверяемом условии или невыполненном блоке может скрываться ошибка выполнения. Например, деление на ноль вызовет ZeroDivisionError только тогда, когда Python действительно попытается выполнить деление.

Ошибка в пропущенном условии 
num = 1

if num == 1:
    print("one")
elif num / 0 == 2:
    print("two")
else:
    print("other")
Консоль
one

Здесь первая ветка сработала, поэтому выражение num / 0 не вычисляется. Если заменить начальное значение на 2, первое условие станет ложным, Python начнёт проверять elif и остановится с ZeroDivisionError. Аналогично может скрываться ошибка в теле пропущенной ветки, например обращение к неопределённому имени.

Синтаксические ошибки не скрываются таким способом. Перед запуском файла Python разбирает весь его синтаксис, включая пропускаемые ветки. Пропущенное двоеточие или неправильная структура отступов помешают запуску, даже если соответствующее условие должно быть ложным. Проверяйте программу на данных для разных веток.

Совет

Если else отсутствует

Если переменная создаётся только в условной ветке, при ложном условии она может остаться неопределённой. Например, после if temperature > 40: с присваиванием msg = "extreme heat" вызов print(msg) при температуре 15 вызовет NameError в отдельно запущенном файле. Заранее задайте подходящее значение по умолчанию или добавьте ветку для оставшихся случаев.

05 / Порядок проверок и границы

Поскольку цепочка останавливается на первой подходящей ветке, порядок условий влияет на результат. Особенно легко ошибиться с условиями, которые охватывают друг друга. Например, любое число, подходящее под temperature <= 10, подходит и под temperature <= 40.

Посмотрите на ошибочный порядок проверок. Введите 15. Программа запустится и выведет результат, но выберет не ту категорию, которую мы ожидаем.

Ошибка в логике: широкое условие первым 
temperature = float(input("Enter temperature: "))

if temperature <= 40:
    msg = "hot"
elif temperature <= 30:
    msg = "warm"
elif temperature <= 20:
    msg = "moderate"
elif temperature <= 10:
    msg = "cool"
elif temperature <= 0:
    msg = "cold"
elif temperature <= -20:
    msg = "extreme cold"

print(msg)
Консоль
Enter temperature: 15
hot

Уже первое сравнение 15 <= 40 истинно, поэтому msg получает "hot". До temperature <= 20, где мы хотели выбрать "moderate", выполнение не доходит. Более широкое условие перекрыло более узкие.

В этой цепочке ни один блок elif не может быть выбран. Если температура не больше 40, сработает первый блок. Если температура больше 40, все перечисленные сравнения будут ложными. Во втором случае в отдельно запущенном файле переменная msg не получит значения и команда print(msg) вызовет NameError.

Для этой задачи можно сохранить проверки с > и двигаться от высоких температур к низким, как в разделе 04. Другой вариант: использовать <= и двигаться от низких границ к высоким. Тогда каждое следующее условие охватывает оставшуюся часть диапазона.

Исправление: проверяем границы снизу вверх 
temperature = float(input("Enter temperature: "))

if temperature <= -20:
    msg = "extreme cold"
elif temperature <= 0:
    msg = "cold"
elif temperature <= 10:
    msg = "cool"
elif temperature <= 20:
    msg = "moderate"
elif temperature <= 30:
    msg = "warm"
elif temperature <= 40:
    msg = "hot"
else:
    msg = "extreme heat"

print(msg)
Консоль
Enter temperature: 15
moderate

При температуре 15 первые три сравнения ложны, а 15 <= 20 истинно. Выбирается "moderate". Дублировать нижнюю границу в этом elif не требуется: предыдущая ложная проверка уже означает, что температура больше 10.

Границы категорий в исправленной программе
ТемператураРезультат
temperature <= -20extreme cold
-20 < temperature <= 0cold
0 < temperature <= 10cool
10 < temperature <= 20moderate
20 < temperature <= 30warm

temperature > 40extreme heat
Совет

Проверяйте саму границу и значения рядом

Знаки > и >= отличаются ровно на границе. Температура 20 здесь относится к moderate, а 20.1 уже к warm. Для каждой границы запустите программу с числом чуть меньше, ровно на границе и чуть больше.

Например, для границы -20 подойдут -20.1, -20 и -19.9. Ожидаемые результаты: extreme cold, extreme cold, cold. Для кассы отдельно проверьте количество 9, 10, 11 и суммы 199, 200, 201: слово «от» в правиле включает сам порог.

06 / Вложенные условные конструкции

Внутри выбранной ветки можно разместить ещё один if. Он будет проверяться только после входа во внешнюю ветку. Это называется вложенной условной конструкцией. Такой порядок полезен, когда следующий вопрос имеет смысл только после положительного ответа на предыдущий.

Представим сервис аренды устройств. Сначала нужен аккаунт, затем активная подписка, затем свободное устройство, а у выбранного устройства должно быть хотя бы 20% заряда. Запрашивать заряд до проверки наличия устройства не нужно.

В этом примере отвечайте на вопросы ровно yes или no маленькими буквами, без дополнительных пробелов. Программа сравнивает ответ со строкой "yes"; любой другой ответ попадёт в соответствующий else. Заряд вводите целым числом от 0 до 100.

Вложенные запросы: следующий вопрос зависит от ответа 
has_account = input("Do you have an account? (yes/no): ")

if has_account == "yes":
    has_subscription = input("Is your subscription active? (yes/no): ")
    if has_subscription == "yes":
        has_device = input("Is a device available? (yes/no): ")
        if has_device == "yes":
            battery_level = int(input("Enter battery level: "))
            if battery_level >= 20:
                print("Device rental approved")
            else:
                print("Charge the device first")
        else:
            print("No device available")
    else:
        print("Activate your subscription")
else:
    print("Create an account first")

print("Request processed")
Консоль
Do you have an account? (yes/no): yes
Is your subscription active? (yes/no): yes
Is a device available? (yes/no): yes
Enter battery level: 15
Charge the device first
Request processed
  1. Если аккаунта нет, выполняется внешний else. Вопросы о подписке, устройстве и заряде вообще не задаются.
  2. Если аккаунт есть, программа заходит в первый блок и спрашивает о подписке. При неактивной подписке выдаёт сообщение и пропускает более глубокие запросы.
  3. При активной подписке задаётся вопрос о доступном устройстве. Только при ответе yes запрашивается заряд.
  4. Последняя проверка выбирает разрешение на аренду или просьбу зарядить устройство. При вводе 15 условие battery_level >= 20 ложно.
  5. В конце при любом из этих исходов выводится Request processed. Команда стоит без отступа после всей конструкции и не повторяется в каждой ветке.

Каждый новый уровень добавляет ещё четыре пробела. Четвёртый if начинается с двенадцати пробелов, а команда в его теле с шестнадцати. Чтобы понять, к какому if относится else, сравните их отступы. Они должны начинаться в одной колонке.

Теперь изменим ситуацию: все данные уже получены заранее. Зададим четыре переменные и сначала оставим вложенную структуру. Во всех отказах пока будет одинаковое сообщение.

Готовые данные: четыре вложенных if/else 
has_account = True
has_subscription = True
has_device = True
battery_level = 15

if has_account:
    if has_subscription:
        if has_device:
            if battery_level >= 20:
                print("Device rental approved")
            else:
                print("Device rental denied")
        else:
            print("Device rental denied")
    else:
        print("Device rental denied")
else:
    print("Device rental denied")

print("Request processed")
Консоль
Device rental denied
Request processed

При заданных значениях первые три условия истинны, а заряда не хватает. Выполняется самый глубокий else. Но если отказ одинаково обрабатывается при любой причине, эту структуру можно сократить: для разрешения должны одновременно выполняться все четыре условия.

Те же данные: одно условие с and 
has_account = True
has_subscription = True
has_device = True
battery_level = 15

if has_account and has_subscription and has_device and battery_level >= 20:
    print("Device rental approved")
else:
    print("Device rental denied")

print("Request processed")
Консоль
Device rental denied
Request processed

and требует истинности каждого условия. Как только встречается ложное, оставшаяся часть выражения не вычисляется. Для готовых значений и одинакового сообщения об отказе эта запись сохраняет поведение вложенного варианта. Общая команда print("Request processed") снова находится после ветвления.

Если пользователю нужно объяснить конкретную причину отказа, проверим проблемы по очереди. Здесь not has_account означает «аккаунта нет», а battery_level < 20 означает «заряда недостаточно». При успешном прохождении всех проверок сработает завершающий else.

Те же данные: первая конкретная причина отказа 
has_account = True
has_subscription = True
has_device = True
battery_level = 15

if not has_account:
    print("Create an account first")
elif not has_subscription:
    print("Activate your subscription")
elif not has_device:
    print("No device available")
elif battery_level < 20:
    print("Charge the device first")
else:
    print("Device rental approved")

print("Request processed")
Консоль
Charge the device first
Request processed

При исходных значениях первые три проверки проблем ложны, четвёртая истинна. Поэтому вместо общего отказа выводится просьба зарядить устройство. Если одновременно нет аккаунта и устройства, программа сообщит только об аккаунте: цепочка показывает первую найденную проблему в выбранном порядке.

Совет

Выбирайте запись по задаче

  • Сохраняйте вложенность, если внутри ветки нужно получить новые данные или выполнить действия перед следующей проверкой. Перенос всех input() наверх изменит диалог: программа начнёт спрашивать даже то, что ей ещё не нужно.
  • Объединяйте условия через and, если значения уже есть, нужны все условия сразу и у отказов одинаковая обработка.
  • Используйте if/elif/else с проверками проблем, если нужно назвать первую причину отказа. Порядок задаёт, о какой проблеме сообщить раньше.
  • Выносите общие действия после ветвления, если они нужны при любом исходе. Если общее действие использует переменную из веток, убедитесь, что она получает значение на каждом возможном пути.

07 / Самопроверка

Вопрос

Что покажется в терминале?

Число и строка 
num = 1

if num == "1":
    print("one")
else:
    print("not one")
Отметьте верные варианты.

1 и "1" имеют разные типы и не равны. Условие ложно, выполняется else.

Сравнение не превращает строку в число: 1 == "1" даёт False.

Проверка равенства int и str допустима. В этом случае она возвращает False.

Двоеточия, отступы и расположение else корректны.

Вопрос

Что покажется в терминале?

Отдельные if 
num = 1

if num == 1:
    print("one")
if num == 2:
    print("two")
else:
    print("not one and not two")
Отметьте верные варианты.

Первый if истинный, поэтому сначала выводится one.

Второй if ложный. Его else выводит эту строку после one. Текст сообщения не меняет логику: здесь он неточно описывает значение num.

Сравнения целых чисел допустимы, строки можно выводить через print.

Два отдельных if допустимы. else относится ко второму if на том же уровне отступа.

Вопрос

Что покажется в терминале?

Пропущенный elif 
num = 1

if num == 1:
    print("one")
elif num / 0 == 2:
    print("two")
else:
    print("not one and not two")
Отметьте верные варианты.

Первое условие истинно. Выполняется его блок, затем вся цепочка заканчивается.

До проверки elif выполнение не доходит, потому что первая ветка уже выбрана.

else выбирается, когда ни одно условие цепочки не оказалось истинным. Здесь первый if истинен.

Выполняемые сравнение целых чисел и вывод строки допустимы.

Деление на ноль записано синтаксически правильно. Проблема возникла бы при его вычислении.

Операция num / 0 не вычисляется: Python пропускает оставшиеся условия цепочки.

Вопрос

Какие формы условной конструкции допустимы?

Каждый вариант обозначает одну цепочку на одном уровне отступа. Многоточие условно заменяет нужные условия, двоеточия и блоки команд. Это схемы, а не готовые строки Python; вложенные и отдельные конструкции здесь не рассматриваются.

Отметьте верные варианты.

Самостоятельный if допустим: при ложном условии его блок пропускается.

Один if и завершающий else задают два исхода.

Дополнительная проверка elif допустима и без else.

После дополнительной проверки можно обработать все оставшиеся случаи через else.

Блоков elif может быть несколько; else необязателен.

После нескольких elif можно поставить один завершающий else.

Самостоятельный else без предшествующего if недопустим.

Одна цепочка начинается с if, а не с else.

Самостоятельный elif без начального if недопустим.

Первым в цепочке должен быть if; elif не может начинать её.

В начале этой записи отсутствует обязательный if.

else завершает цепочку; после него нельзя продолжить её через elif.

Вопрос

Что покажется в терминале?

Логический флаг 
grade = 9
is_success = grade >= 7

if is_success:
    print("The student completed the homework")
else:
    print("The student failed to complete the homework")
Отметьте верные варианты.

9 >= 7 даёт True. Флаг is_success истинен, выбирается первый блок.

Для выполнения else флаг должен быть ложным, но здесь он равен True.

Использовать логическую переменную непосредственно после if допустимо.

Вопрос

Что покажется в терминале?

Первое совпадение 
grade = 35

if grade > 10:
    print("Greater than 10")
elif grade > 20:
    print("Greater than 20")
elif grade > 30:
    print("Greater than 30")
else:
    print("Less or equal 10")
Отметьте верные варианты.

35 > 10 истинно. Выбирается первая ветка, оставшиеся условия пропускаются.

Хотя 35 > 20 тоже истинно, Python уже выбрал предыдущую ветку и не проверяет этот elif.

Python не ищет самую узкую или последнюю подходящую ветку. Он выбирает первую.

else не выполняется, потому что первое условие цепочки истинно.

Запись допустима. Порядок проверок может не соответствовать замыслу, но синтаксис корректен.
