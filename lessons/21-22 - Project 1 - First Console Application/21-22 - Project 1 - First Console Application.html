01 / Скачать и установить Git

Откройте официальный сайт Git. Перейдите в раздел Install и выберите Windows. Можно сразу открыть страницу установки Git для Windows.

В разделе Standalone Installer скачайте установщик Setup для своего компьютера. Для большинства компьютеров подходит x64. Для Windows на ARM нужен ARM64. Тип системы можно посмотреть в параметрах Windows: «Система» → «О системе». Нужен установщик, а не Portable.

Откройте скачанный файл .exe. Если Windows запросит разрешение на установку, подтвердите его. Проходите установщик кнопкой Next. Обратите внимание на следующие настройки. Проставьте их как указано на картинках.

Здесь выставляем по умолчанию название ветки main.

Здесь добавляем git в PATH, чтобы PowerShell мог находить команду git.

Здесь выбираем Git Credential Manager, чтобы он помогал войти в GitHub через браузер при первой отправке и запоминал вход.

Все остальные настройки не трогайте, просто жмите Next.

Полностью закройте ранее открытые окна PowerShell и Windows Terminal. Через меню «Пуск» откройте Windows PowerShell или новую вкладку PowerShell в Windows Terminal. Выполните проверку.

PowerShell: установлен ли Git
git --version
Пример вывода
git version 2.56.0.windows.1

Номер выше приведён как пример: ваша версия может отличаться. Важно, что команда вывела строку с версией и не сообщила об ошибке.

02 / Зарегистрироваться на GitHub

Если у вас уже есть личный аккаунт GitHub, войдите в него и проверьте подтверждение почты. Создавать второй аккаунт для этого проекта не нужно.

  1. Откройте регистрацию GitHub. Создайте бесплатный личный аккаунт, следуя подсказкам формы. При регистрации по электронной почте укажите свой адрес и задайте пароль.
  2. Выберите свободное имя пользователя, username. Оно будет частью адресов ваших репозиториев. Например, у учебного пользователя tom-student профиль имеет адрес https://github.com/tom-student. Это пример, у вас будет своё имя.
  3. Выполните предложенную проверку и подтвердите электронную почту по письму GitHub. Если письма нет, проверьте папку спама и адрес в форме. Подтверждённая почта нужна для основных действий, включая создание репозитория.
  4. Войдите в аккаунт. Откройте меню своей аватарки в правом верхнем углу и выберите Your profile. Посмотрите username на странице и в её адресной строке.

Username может отличаться от отображаемого имени в профиле и от имени автора коммитов. В ссылку на репозиторий мы подставляем именно username.

03 / Один раз настроить имя и почту

Определение

Коммит

Коммит в Git фиксирует состояние отслеживаемых файлов проекта в истории. Это контрольная точка: позже можно посмотреть, что изменилось по сравнению с предыдущей версией, и вернуться к сохранённому состоянию. У коммита есть уникальный идентификатор, сведения об авторе, время и сообщение с описанием изменений.

В каждом коммите Git записывает автора. Настроим имя и почту до первого собственного коммита. Это подпись в истории: она не выполняет вход в GitHub и не подтверждает права на репозиторий.

Для проверки автора вызовите команды, указанные ниже.

PowerShell: проверить автора
git config --global user.name
git config --global user.email
git config --global init.defaultBranch
Пример вывода
Tom Student
student@example.com
main

Поменять их можно следующими командами.

PowerShell: настроить автора
git config --global user.name "Tom Student"
git config --global user.email "student@example.com"
git config --global init.defaultBranch main

Вместо Tom Student укажите своё имя, например имя и фамилию латиницей. Вместо student@example.com укажите подтверждённую почту своего GitHub-аккаунта или точный адрес noreply из настроек. Учебный адрес из примера не используйте для своих коммитов. init.defaultBranch отвечает за ветку по умолчанию (обычно это main).

Внимание

Выберите почту до создания коммитов

Почта автора сохраняется в истории. После публикации репозитория её смогут увидеть другие люди. Чтобы скрыть личный адрес, откройте GitHub: аватарка → Settings → Emails, включите Keep my email addresses private и скопируйте показанный GitHub адрес noreply. Не составляйте его по шаблону: используйте точное значение из своего аккаунта. Поздняя смена настройки Git не меняет почту в уже созданных коммитах.

Параметр --global применяет настройку ко всем вашим Git-репозиториям в текущей учётной записи Windows. Обычно её достаточно выполнить один раз.

04 / Клонировать репозиторий преподавателя

Определение

Репозиторий: локальный и удалённый

Репозиторий в Git хранит версии файлов проекта и историю их изменений в виде коммитов. Благодаря этой истории можно сравнить версии и узнать, кто и что изменил.

  • Локальный репозиторий находится на вашем компьютере. Обычно это служебная папка .git внутри папки проекта, рядом с файлами, которые вы редактируете. Создавать коммиты и просматривать сохранённую историю можно без интернета.
  • Удалённый репозиторий находится по отдельному адресу, в нашем случае на GitHub. Через него можно делиться проектом и получать изменения с другого компьютера.

Получите у преподавателя ссылку на учебную заготовку, предназначенную для копирования студентами. Для проекта Student Profile примером служит репозиторий task-student-profile. Если преподаватель выдал другой адрес или отдельную версию после занятия, используйте выданную ссылку.

Откройте репозиторий в браузере. На вкладке Code нажмите кнопку Code, выберите HTTPS и скопируйте адрес, заканчивающийся на .git.

В Проводнике откройте папку, куда собираетесь клонировать репозиторий. Например, C:\Users\Tom\Python Bootcamp. В этой папке откройте PowerShell. Дальше введите git clone <URL.git> <REPO-NAME>, где вместо <URL.git> вставьте скопированный HTTPS, а вместо <REPO-NAME> укажите название. Например, может получится как указано ниже.

PowerShell: шаблон клонирования
git clone https://github.com/Zeyafix/task-student-profile.git first-console-application
cd first-console-application

Команда clone скачивает файлы и историю, создаёт локальный репозиторий и запоминает исходный адрес под именем origin. Последнее слово в команде задаёт имя новой папки на вашем компьютере. Переходите в неё только после успешного клонирования. Если папка с таким именем уже существует и содержит файлы, не удаляйте её: проверьте, не ваш ли это готовый клон, или выберите другую родительскую папку.

Выполните следующие команды, чтобы проверить репозиторий.

PowerShell: проверить полученный клон
git status
git log --oneline -n 5

В status вы увидите текущую ветку и состояние файлов, а в log несколько коммитов. Сообщения и идентификаторы зависят от её версии.

Выполните ещё одну команду.

PowerShell: адрес сразу после клонирования
git remote -v
Пример вывода
origin  https://github.com/Zeyafix/task-student-profile.git (fetch)
origin  https://github.com/Zeyafix/task-student-profile.git (push)

Строка fetch показывает адрес для получения, push для отправки. Сейчас обе ведут к преподавателю. В следующем разделе заменим их своим адресом. Скрытую папку .git не трогайте, в ней находится история и настройки.

05 / Связать клон со своим репозиторием

Теперь создадим место для вашей работы на GitHub. Локальный клон уже содержит историю преподавателя, поэтому новый удалённый репозиторий должен быть пустым.

Войдите в свой GitHub-аккаунт. В верхнем меню «+» выберите New repository.

В Owner выберите свой личный аккаунт. В Repository name введите название репозитория, например first-console-application. Убедитесь, что такого репозитория в аккаунте ещё нет. Выберите Public, чтобы другие пользователи могли видеть, что находится в репозитории (если вы не собираетесь ни с кем делиться своим репозиторием, то ставьте Private). Оставьте выключенным добавление README, для .gitignore и License выберите вариант без добавления. Эти файлы сейчас создавать на сайте не нужно. Нажмите Create repository.

На странице пустого репозитория выберите HTTPS и скопируйте адрес. Не выполняйте все предложенные GitHub команды: репозиторий на компьютере у вас уже есть, нужна только ссылка.

Вернитесь в PowerShell, где открыт ваш репозиторий. Введите git remote set-url origin <URL.git>. У вас получится что-то подобное:

PowerShell: заменить адрес origin
git remote set-url origin https://github.com/tom-student/first-console-application.git

Затем выполните команду git remote -v, чтобы проверить наличие удалённого репозитория. Вы увидите что-то подобное:

PowerShell: проверить свой адрес
git remote -v
Пример вывода
origin  https://github.com/tom-student/first-console-application.git (fetch)
origin  https://github.com/tom-student/first-console-application.git (push)

Команда set-url меняет сохранённый адрес. Существующие файлы, коммиты и авторство остаются теми же, что изначально были в клонированном репозитории, а все последующие действия будут связаны с вашим удалённым репозиторием. origin отражает название удалённого репозитория.

Выполните следующий код, чтобы проверить ветку.

PowerShell: проверить текущую ветку
git status

В строке On branch main имя текущей ветки уже подходящее. Если вместо main указано другое имя, например master, один раз переименуйте текущую ветку в этом локальном учебном клоне:

PowerShell: только если ветка называется иначе
git branch -M main

Эта команда переименовывает текущую ветку. В нашем маршруте используем одну ветку main. До первой отправки status ещё может упоминать старую связь с origin/master или origin/main: это сохранённые сведения клона, а не проверка содержимого нового сайта. Дальше первой отправкой с -u мы зададим нужную связь.

06 / Изменения и коммиты

Команда git status отвечает на вопрос «Что сейчас происходит в рабочей папке?». Она ничего не сохраняет и не отправляет. Запускайте её перед подготовкой изменений, перед коммитом и после него. Ниже показаны сокращённые фрагменты вывода: подсказки Git и сведения о связи с удалённой веткой могут занимать дополнительные строки.

Как читать git status
Фрагмент выводаЧто он означает
On branch mainВы работаете в ветке main.
Untracked files:Новые файлы, которые Git ещё не отслеживает. Они не попадут в коммит сами.
Changes not staged for commit:Изменения отслеживаемых файлов ещё не подготовлены для следующего коммита.
Changes to be committed:Эти изменения уже подготовлены и попадут в следующий коммит.
modified: main.pyФайл main.py изменён. Смотрите, под каким заголовком находится эта строка: именно заголовок определяет, подготовлен ли он.
nothing to commit, working tree cleanНет подготовленных или незафиксированных изменений и неотслеживаемых файлов, которые показывает status. Игнорируемые файлы могут оставаться в папке.

Проследим за одним файлом main.py. Этот раздел показывает весь переход между состояниями, а следующий подробно объясняет подготовку и коммит. Если пройдёте пример сейчас, повторно делать тот же коммит в разделе 08 не нужно.

  1. Откройте папку клона в редакторе кода. Если main.py ещё нет, создайте его в корне проекта. Если файл уже есть, сохраните существующую программу и добавьте одну отдельную строку приветствия в подходящем месте print("Hello, student!"). Не заменяйте весь проект учебным примером.
  2. Введите строку из блока ниже и сохраните файл через Ctrl + S. Затем вернитесь в PowerShell, который открыт в папке проекта, и выполните git status.
PowerShell: после сохранения существующего файла
git status
Пример вывода
On branch main
Changes not staged for commit:
  modified:   main.py

Если файл создан впервые, вместо этого вы увидите Untracked files: и под ним main.py. Это значит, с файлом main.py произошли изменения (его только добавили, изменили или удалили) и эти изменения пока не запомнились гитом.

Вызовем команду, чтобы гит запомнил текущие изменения файла main.py.

PowerShell: подготовить файл и проверить
git add main.py
git status
Пример вывода
On branch main
Changes to be committed:
  modified:   main.py

Описание после вызова команды add может отличаться. Гит запомнил текущий вариант файла main.py для следующего коммита.

Теперь зафиксируем подготовленные изменения с помощью git commit -m "Add greeting".

PowerShell: зафиксировать подготовленное изменение
git commit -m "Add greeting"
git status
Пример вывода
[main a1b2c3d] Add greeting
 1 file changed, 1 insertion(+)
On branch main
nothing to commit, working tree clean

Команда commit создаёт контрольную точку изменений. Параметр -m позволяет через пробел в кавычках кратко указать комментарий. Обычно в комментариях кратко указывают действия в повелительном наклонении, которые отражают изменения.

Идентификатор a1b2c3d условный, у вас будет другой. Если кроме main.py вы изменяли другие файлы, они могут остаться в status. Чистая папка в примере означает, что это было единственное изменение.

Совет

Когда изменилось несколько файлов

Из корня проекта git add . готовит все неигнорируемые новые файлы и изменения в текущей папке и вложенных папках, включая удаления отслеживаемых файлов. Точка означает текущую папку. Сначала просмотрите список: случайный файл тоже может попасть в коммит.

PowerShell: подготовка всех нужных изменений
git status
git add .
git status

Перед коммитом убедитесь, что в группе Changes to be committed только нужные файлы. Если сомневаетесь, используйте git add с именами отдельных файлов.

Чтобы увидеть краткую историю коммитов, полезна следующая команда:

PowerShell: последние коммиты
git log --oneline -n 5
Пример вывода
a1b2c3d Add greeting
83d29ab First commit

--oneline выводит по одной короткой строке на коммит, -n 5 ограничивает список пятью последними коммитами. Если коммитов меньше, строк будет меньше. Новые стоят сверху. Слева короткий идентификатор, справа сообщение автора. Git также может показать имена веток в скобках.

log показывает локальную историю. Он не показывает правки, которые ещё не закоммичены, и не доказывает, что коммит отправлен на GitHub. Даже чистый status возможен до публикации: это состояние рабочей папки, а не проверка сайта.

В корне репозитория создайте файл .gitignore и впишите в него следующее:

Файл .gitignore: типичные исключения Python
.venv/
__pycache__/
.env

В файле .gitignore вписываются пути/файлы, которые не должны отслеживаться гитом. .venv/ исключает папку локального виртуального окружения, __pycache__/ служебный кэш Python, .env файл локальных настроек, где могут находиться секреты. Если этих файлов ещё нет, правила могут пригодиться позже.

Сам .gitignore нужно добавить в Git и закоммитить, например командой git add .gitignore и обычным коммитом с сообщением Add Python ignore rules.

07 / Отправить коммиты на GitHub

Проверьте направление отправки ещё раз командой git remote -v. В обеих строках должны быть ваш username и ваш first-console-application. Если там всё ещё заготовка преподавателя, вернитесь к разделу 04 и исправьте адрес.

Если указан ваш удалённый репозиторий, то выполните команду git push -u origin main. Здесь push отвечает за отправление локальных коммитов, origin за имя удалённого репозитория, main за локальную ветку. Параметр -u позволяет запомнить локальную ветку и удалённый репозиторий, чтобы все последующие вызовы git push по умолчанию считались как git push origin main. Если в удалённом репозитории отсутствует ветка main, то она создастся автоматически.

При первом обращении, требующем входа, Git Credential Manager предложит авторизацию. Если вход уже сохранён, окно может не появиться. Клонирование публичной заготовки обычно не требует входа, а отправка в ваш репозиторий требует.

  1. Если появилось окно Git Credential Manager, выберите вход через браузер, обычно Sign in with your browser.
  2. В открывшемся браузере проверьте аккаунт: нужен тот, которому принадлежит ваш репозиторий. Войдите в него.
  3. Подтвердите запрос авторизации Git Credential Manager, если он показан. Дождитесь сообщения об успешном входе.
  4. Вернитесь в PowerShell и дождитесь завершения push. После успешного входа менеджер сохранит учётные данные для последующих обращений.

После успешного push, обновите страницу репозитория в браузере: вместо инструкции для пустого репозитория должны появиться файлы и последний коммит.

push отправляет коммиты. Несохранённый текст редактора, сохранённые правки без add и подготовленные правки без commit на сайте GitHub не появятся.

Команда git pull получает изменения из связанного удалённого репозитория и применяет их к текущей локальной ветке. В нашем случае это обновление main из своего origin. Когда над проектом работают несколько человек, обычно перед push делают git pull.

Внимание

Чистая папка и совместимая история различаются

Перед каждым pull проверяйте status и завершайте текущую работу. Локальный коммит сохраняет её в истории, но сам по себе не гарантирует отсутствие конфликта. Например, если вы изменили одну и ту же строку локально и через сайт, Git может попросить решить, какой вариант оставить.

Если обычный push отклонён из-за новых коммитов на GitHub, сначала получите их через pull при чистой рабочей папке. После успешного объединения проверьте программу и повторите push.

Частый сценарий — на другом устройстве один раз клонируют репозиторий, затем используют pull перед работой, чтобы быть на последней версии коммитов.

Подсказка

Как отправить ссылку на свою работу

  1. Откройте главную страницу своего репозитория на GitHub и обновите её. Проверьте, что видны ваши последние изменения и нужные файлы проекта.
  2. Скопируйте адрес из адресной строки браузера, например https://github.com/tom-student/first-console-application.
  3. Чтобы другие люди видели репозиторий, он должен быть публичным (Public). Откройте скопированную ссылку в приватном окне браузера без входа в GitHub и убедитесь, что файлы доступны.

08 / Создания своего репозитория с нуля

Предположим требуется создать полностью новый и чистый репозиторий.

  1. Выберите существующую родительскую папку для проектов вне других Git-репозиториев. Перейдите в неё в PowerShell.
  2. Создайте новую пустую папку (например, test) и перейдите в неё.
  3. Создайте файл README.md в этой папке и поместите в него # Заголовок файла.

На GitHub создайте новый репозиторий (например, test) под своим аккаунтом: Public, без README, .gitignore и лицензии, как делали раннее. Скопируйте его HTTPS-адрес. Перед выполнением следующего блока замените <username> своим username, а <repo_name> на название вашего репозитория, вместе с угловыми скобками (например, test). Выполняйте строки по очереди.

git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/<username>/<repo_name>.git
git push -u origin main

09 / Исправление последнего коммита

Представьте, что вы сделали коммит с небольшим изменением main.py, но сразу заметили опечатку в этом же изменении. Если это ваш последний коммит и вы его ещё не отправляли, его можно заменить исправленной версией. Для этого достаточно вызвать git commit --amend --no-edit.

--amend заменяет последний коммит новым с учётом подготовленных изменений. --no-edit сохраняет прежний комментарий к коммиту.

Если старый вариант не был отправлен на GitHub, обычного git push достаточно.

Для обычной дальнейшей работы по-прежнему подходят новые коммиты.

Внимание

Проверьте, был ли старый вариант на GitHub

Если же перед локальными изменениями вы уже отправили старый коммит, то после amend локальная и удалённая истории разойдутся. Обычный push может быть отклонён. Поэтому есть два способа, как действовать дальше.

Первый вариант и наиболее простой — сохранить исправление отдельным обычным коммитом вместо amend, затем с помощью git push отправить на GitHub.

Второй вариант — выполнить git push --force-with-lease. При выполнении этой команды Git сначала убеждается, что удалённая ветка не изменилась с момента, когда её последний раз видели. Если кто-то успел запушить новый коммит, команда обычно откажется перезаписывать его.
