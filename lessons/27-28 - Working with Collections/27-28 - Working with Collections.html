01 / Повторение пройденного

Вопрос

Узнайте коллекцию по свойствам

Нужно хранить текст как неизменяемую последовательность символов. Какой тип предназначен для этого?

Строка хранит последовательность символов и не позволяет менять символ по индексу.

Список хранит элементы по позициям, допускает повторы, добавление и замену элементов.

Кортеж хранит последовательность объектов, но его позиции нельзя заменить после создания.

Множество хранит уникальные хешируемые элементы, позволяет добавление и удаление, не имеет индексов.

Замороженное множество хранит уникальные хешируемые элементы и не позволяет менять свой состав.

Словарь связывает уникальный хешируемый ключ со значением и позволяет изменять эти связи.

Вопрос

Что можно использовать как ключ?

Выберите хешируемые варианты.

Строка хешируема: её можно использовать как ключ словаря и элемент множества.

Список не хешируем, даже когда он пустой.

Все перечисленные в условии элементы хешируемы, поэтому и такой кортеж хешируем.

Для хешируемости кортежа нужен хешируемый элемент на каждой позиции. Вложенная нехешируемая коллекция нарушает это условие.

Изменяемое множество не хешируемо.

Замороженное множество хешируемо; при создании оно уже требует хешируемые элементы.

Сам словарь не хешируем. Хешируемыми должны быть его ключи.

Целые числа хешируемы.

Числа float хешируемы. Хешируемость не означает уникальности каждого возможного ключа: например, 1 и 1.0 равны.

Логические значения хешируемы, но True и 1 равны и обращаются к одной записи словаря.

02 / Как выбирать коллекцию под задачу

Начинайте с действий над данными. Слова «несколько значений» ещё не подсказывают тип: нужно понять, что означает один элемент и как программа будет его использовать.

От требований к коллекции
ЗадачаТребованияВыбор и пример
Очередь песенПорядок воспроизведения важен, песня может повториться, а очередь редактируют.list: ["Rain", "Sun", "Rain"]
Координаты точкиДве позиции с разным смыслом: сначала x, затем y, нужна фиксированная пара.tuple: (3, 7)
Уникальные участникиХраним ID, повторное участие не создаёт второго элемента, состав может меняться.set: {"s01", "s02"}
Разрешённые действияВажна принадлежность действию набора, порядок не нужен, состав фиксирован.frozenset: frozenset(["read", "write"])
Телефонная книгаПо уникальному имени контакта нужно получить номер и при необходимости обновить его.dict: {"Alex": "+994501112233"}

Коллекции и типы данных подбираем от требований:

  1. Определить один элемент: песня, ID, пара координат или запись с полями.
  2. Решить, несут ли повторения информацию. Две одинаковые песни в очереди могут быть намеренными.
  3. Уточнить, нужен ли порядок и доступ по позиции.
  4. Проверить, будет ли меняться состав или значение на позиции.
  5. Выбрать способ поиска: позиция, известный ключ или проверка принадлежности.
Подсказка

Выбор зависит от условия

Одна задача допускает разные решения. Если координаты нужно постоянно менять по отдельности, может подойти список. Если у контактов повторяются имена, используйте уникальные ID как ключи. Неизменяемый набор разрешений тоже можно заменить целиком новым объектом. Обосновывайте выбор нужными операциями. Универсальной коллекции нет.

03 / Сравнение свойств коллекций

У последовательности важны позиции. У словаря важна связь ключа со значением. У множества важна принадлежность элемента. Сравните эти три способа организации данных до написания кода.

Обратите внимание

Неизменяемость и хешируемость

Ключи dict и элементы set или frozenset должны быть хешируемыми. Для изученных типов это означает, что их можно использовать в хеш-поиске. У такого объекта хеш не меняется в течение жизни, а равные объекты имеют одинаковый хеш. list, set и dict не хешируемы. tuple хешируем только при хешируемости всех его элементов. Неизменяемость внешнего контейнера не замораживает вложенные объекты.

04 / Одна задача и разные способы хранения

В группе учатся Alex, Mia и ещё один Alex. Имя не определяет человека однозначно. Присвоим студентам ID s01, s02 и s03 и сравним три формы хранения.

Что сохраняет форма данных
ФормаЧто известноПоиск по ID
["Alex", "Mia", "Alex"]Имена, их порядок и повторенияID не сохранены, восстановить связь нельзя
[("s01", "Alex"), ("s02", "Mia"), ("s03", "Alex")]Пары ID и имени, порядок, возможны повторные IDПеребирать пары и сравнивать ID
{"s01": "Alex", "s02": "Mia", "s03": "Alex"}Для каждого уникального ID одно имяОбратиться по известному ключу
Один запрос к двум структурам
names = ["Alex", "Mia", "Alex"]
pairs = [("s01", "Alex"), ("s02", "Mia"), ("s03", "Alex")]
students = {"s01": "Alex", "s02": "Mia", "s03": "Alex"}
target_id = "s03"
for student_id, name in pairs:
    print("Check:", student_id)
    if student_id == target_id:
        print("Found:", name)
        break
print("By key:", students[target_id])
print("Names:", len(names))
print("Unique names:", len(set(names)))
Консоль
Check: s01
Check: s02
Check: s03
Found: Alex
By key: Alex
Names: 3
Unique names: 2
  1. В списке пар цикл сначала проверяет s01, затем s02. Они не совпадают с искомым ID.
  2. Пара s03 подходит. Выводим имя и прекращаем поиск через break.
  3. Для словаря известен ключ s03: Python использует механизм поиска по ключу, нашему коду не нужен цикл по остальным записям.
  4. Множество имён оставляет два разных имени. По нему нельзя узнать, что студентов трое и двоих зовут Alex.

Список имён подходит, если нужен только порядок выступлений. Для журнала с поиском по ID удобнее словарь. Множество имён отвечает на вопрос «какие имена встречаются», но не заменяет реестр людей. Проверку неизвестного ID разберём в разделе 08.

05 / Преобразование коллекций и потеря данных

Преобразование меняет форму хранения. Оно не обязано сохранять всю информацию.

Одна последовательность, четыре коллекции
data = ["red", "blue", "red"]
as_list = list(data)
as_tuple = tuple(data)
as_set = set(data)
as_frozen = frozenset(data)
restored = list(as_set)
print(data)
print(as_list)
print(as_tuple)
print(sorted(as_set))
print(sorted(as_frozen))
print(len(restored))
Консоль
['red', 'blue', 'red']
['red', 'blue', 'red']
('red', 'blue', 'red')
['blue', 'red']
['blue', 'red']
2

Для множеств выводим sorted(): он создаёт отсортированный список только для показа, сами as_set и as_frozen остаются множествами. Поэтому вывод стабилен. Напрямую печатать множество тоже можно, но порядок его элементов не является обещанием Python.

Что осталось после преобразования
РезультатСоставСвойства

print(list(data))
print(list(data.values()))
print(list(data.items()))

Консоль
['s01', 's02']
['Alex', 'Alex']
[('s01', 'Alex'), ('s02', 'Alex')]

Обычный list(data) перебирает ключи. values() даёт значения, items() даёт пары. dict(pairs) читает пары по очереди: поздняя пара для s01 заменяет Alex на Sam. Две записи под одним равным ключом сохранить нельзя, а позиция ключа s01 остаётся первой.

Структура

Договоримся о данных

ID являются строками и уникальны внутри журнала. name и group тоже строки. scores всегда список чисел, в наших примерах целых оценок от 1 до 12, но может быть пустым. Все записи содержат эти три обязательных поля. Необязательное поле note может отсутствовать. Одинаковые поля позволяют одному циклу обработать каждого студента без догадок о форме записи.

Пустой scores означает, что студент существует, но пока не имеет оценок. Пустой students означает, что журнал вообще не содержит студентов. В следующих примерах исходные данные снова указаны в начале каждого блока: изменения из предыдущего блока переносить не нужно.

07 / Чтение по цепочке ключей и индексов

Пусть нужно получить первую оценку Alex. Не пытайтесь прочитать всю цепочку сразу: после каждой пары квадратных скобок получается новое значение. Следующие скобки работают уже с ним.

Сначала промежуточные переменные
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
student = students["s01"]
scores = student["scores"]
first_score = scores[0]
print(student["name"])
print(student["group"])
print(scores)
print(first_score)
print(students["s01"]["scores"][0])
Консоль
Alex
A
[8, 10]
8
8
Чтение students["s01"]["scores"][0]
ШагТекущее значениеТипСледующая операция
НачалоЖурнал studentsdictВыбрать ключ "s01"
После ["s01"]{"name": "Alex", "group": "A", "scores": [8, 10]}dictВыбрать ключ "scores"
После ["scores"][8, 10]listВыбрать индекс 0
После [0]8intИспользовать число в расчёте или выводе

Путь повторяет схему из раздела 06: журнал → запись → список → число. Для имени достаточно students["s01"]["name"], для группы меняем последний ключ на "group". Если нужен весь список оценок, останавливаемся на ["scores"] и не добавляем индекс.

Если ключей нет, то при обращении к первому несуществующему ключу возникнет ошибка.

Нет внешнего ключа
students = {}
print(students["s99"]["name"])
Ошибка: тип исключения
KeyError (выполнение остановлено)

Ошибка возникает на первом шаге, students["s99"]. Внутренний словарь не найден, поэтому до ["name"] выполнение не доходит.

Если запись есть, но ошибиться в названии поля, например написать "score" вместо "scores", KeyError возникнет уже на втором шаге.

Нет внутреннего ключа
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
print(students["s01"]["score"])
Ошибка: тип исключения
KeyError (выполнение остановлено)

Аналогично с индексами.

Нет позиции в списке
students = {"s01": {"name": "Alex", "group": "A", "scores": []}}
print(students["s01"]["scores"][0])
Ошибка: тип исключения
IndexError (выполнение остановлено)

Здесь оба ключа существуют. На третьем шаге программа пытается получить позицию 0 из пустого списка. IndexError сообщает о неверном индексе, а не об отсутствии студента.

Для каждой коллекции используем свой вариант доступа к элементу.

Неверный тип индекса
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
print(students["s01"]["scores"]["first"])
Ошибка: тип исключения
TypeError (выполнение остановлено)

После двух ключей мы получили list. Его одиночный элемент читается по целочисленному индексу, а строка "first" не подходит. TypeError также возник бы, если по пути вместо ожидаемого словаря оказался None. При поиске ошибки проверяйте тип и значение на каждом шаге.

08 / Отсутствующие записи и пустые значения

Отсутствие бывает разным. ID может не существовать, необязательное поле может быть пропущено, а обязательный список может существовать, но быть пустым. Для каждого случая нужна проверка на своём уровне.

Проверяем уровни по порядку
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
    "s02": {"name": "Mia", "group": "A", "scores": [12]},
    "s03": {"name": "Alex", "group": "B", "scores": []},

for student_id in ["s01", "s03", "s99"]:

    if student_id not in students:
        print("Student not found")
    else:
        student = students[student_id]
        if "note" in student:
            print("Note:", student["note"])
        else:
            print("No note")
        if student["scores"]:
            print("First score:", student["scores"][0])
        else:
            print("No scores")

No note

  1. Сначала in проверяет ключ во внешнем словаре. При неизвестном ID вложенную запись не читаем.
  2. Для найденной записи отдельно проверяем необязательный note. Обязательные name, group и scores предусмотрены договорённостью о данных.
  3. Пустой список даёт False в условии. Индекс 0 читается только в ветке непустого списка.
  4. Для s03 выводится No scores, а для s99 получаем Student not found. Эти состояния нельзя смешивать.

Есть безопасный способ получать значения по несуществующим ключам.

get защищает только свой уровень
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},

    print("Student not found")

in отвечает на вопрос о наличии ключа и не читает значение. get() возвращает значение, а при отсутствии ключа по умолчанию возвращает None. В нашем журнале значением всегда служит словарь, поэтому None однозначно означает отсутствие. Если бы None было разрешённым значением записи, для различения случаев потребовалась бы проверка in.

Однако get() не защищает от следующей ситуации:

Почему одного get недостаточно
students = {}
student_id = "s99"
print(students.get(student_id)["name"])
Ошибка: тип исключения
TypeError (выполнение остановлено)

Вызов get() успешно вернул None. Ошибка возникает после этого: программа пробует выполнить None["name"]. Безопасность первого обращения не распространяется на последующие скобки. Нельзя незаметно подставлять фиктивного студента вместо обязательной отсутствующей записи.

09 / Добавление и изменение вложенных записей

Операция записи похожа на чтение пути, но последний шаг задаёт место изменения. Добавим студента s02 только при свободном ID, затем изменим его группу и оценки. Каждый новый студент получает отдельный словарь и отдельный список.

Добавление, поле и список

При добавлении проверка защищает от перезаписи уже существующего ID. При изменении направление проверки обратное: запись должна существовать. В учебном интерфейсе принимаем только неотрицательные индексы. Условие 0 <= score_index < len(scores) отсекает и отрицательные, и слишком большие значения.

Напомним, что словари являются изменяемой коллекцией. Поэтому через две переменные можно получить доступ к одному и тому же объекту.

Новая запись на каждом шаге
students = {}

[]

10 / Удаление на разных уровнях

Перед удалением укажите уровень: весь студент, необязательное поле или одна оценка. Чем короче путь к удаляемому объекту, тем большую часть журнала затрагивает операция.

Удаляем на трёх уровнях
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10], "note": "Call"},
    "s02": {"name": "Mia", "group": "B", "scores": [12]},
}
student_id = "s01"
if student_id in students:
    student = students[student_id]
    if "note" in student:
        del student["note"]
    print("Without note:", student)
    score_index = 0
    if 0 <= score_index < len(student["scores"]):
        removed_score = student["scores"].pop(score_index)
        print("Removed score:", removed_score)
    else:
        print("Invalid score index")
    print("Remaining:", student)
else:
    print("Student not found")
student_id = "s02"
if student_id in students:
    removed_student = students.pop(student_id)
    print("Removed student:", removed_student["name"])
else:
    print("Student not found")
print("IDs:", list(students))
Консоль
Without note: {'name': 'Alex', 'group': 'A', 'scores': [8, 10]}
Removed score: 8
Remaining: {'name': 'Alex', 'group': 'A', 'scores': [10]}
Removed student: Mia
IDs: ['s01']
  1. del student["note"] убрал только необязательное поле. Проверка in не дала обратиться к отсутствующему ключу.
  2. pop(0) списка удалил оценку на позиции 0 и вернул её: теперь можно сообщить, что удалено. Оставшаяся оценка 10 сдвинулась на позицию 0.
  3. students.pop("s02") убрал связь ID с целой записью из журнала и вернул эту запись. Переменная removed_student всё ещё позволяет прочитать удалённые данные.
  4. После всех действий s01 существует, поля name, group и scores сохранены. s02 в журнале отсутствует.

Проверка value in scores защищает remove() от отсутствующего значения, иначе возникнет ValueError. Для pop() списка проверяют индекс, для del и pop() словаря проверяют ключ. У pop() словаря можно задать значение по умолчанию для отсутствующего ключа, например student.pop("note", None). У pop() списка такого аргумента по умолчанию нет.

Верный подход

Пустое поле остаётся частью записи

Чтобы убрать все оценки, очищайте scores. Удаление самого обязательного поля нарушит договорённость о структуре: последующий student["scores"] вызовет KeyError. Удалять поле целиком здесь допустимо только для необязательного note.

13 / Подсчёты и статистика

Количество студентов и количество оценок измеряют разные вещи. len(students) считает внешние ключи. Для одного студента считаем элементы его scores. Средняя оценка существует только при наличии хотя бы одной оценки.

Накопители одного студента
students = {

    score_count += 1
    score_total += score
    print("Step:", score_count, score_total)
print("Students:", len(students))
if score_count > 0:
    print("Average:", score_total / score_count)
else:
    print("No scores")

Start: 0 0
Step: 1 8
Step: 2 18
Students: 1
Average: 9.0

14 / Группировка и частоты

Сейчас журнал организован по ID. Для отчёта нужен другой взгляд: по каждой группе получить список её студентов. Исходный журнал можно оставить как есть и построить отдельный словарь group → list_of_student_ids.

Группировка с явной проверкой
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
    "s02": {"name": "Mia", "group": "A", "scores": [12]},
    "s03": {"name": "Alex", "group": "B", "scores": []},
}
groups = {}
for student_id, student in students.items():
    group = student["group"]
    if group not in groups:
        groups[group] = []
    groups[group].append(student_id)
    print(student_id, groups)
Консоль
s01 {'A': ['s01']}
s02 {'A': ['s01', 's02']}
s03 {'A': ['s01', 's02'], 'B': ['s03']}

Ниже ещё один способ через setdefault().

Тот же результат с setdefault
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
    "s02": {"name": "Mia", "group": "A", "scores": [12]},
    "s03": {"name": "Alex", "group": "B", "scores": []},

setdefault(group, []) возвращает список по ключу group. Если ключа ещё нет, метод сначала вставляет предложенный пустой список. Если ключ уже есть, его значение сохраняется. Поэтому append() в обоих случаях дописывает ID именно в список своей группы.

Частоты оценок и уникальные группы
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
    "s02": {"name": "Mia", "group": "A", "scores": [12]},
    "s03": {"name": "Alex", "group": "B", "scores": []},
}
students["s02"]["scores"].append(10)
frequencies = {}
unique_groups = set()
score_count = 0
for student in students.values():
    unique_groups.add(student["group"])
    for score in student["scores"]:
        frequencies[score] = frequencies.get(score, 0) + 1
        score_count += 1
print("Frequencies:", frequencies)
print("Students:", len(students))
print("Scores:", score_count)
print("Different scores:", len(frequencies))
print("Groups:", sorted(unique_groups))
Консоль

Students: 3
Scores: 4
Different scores: 3
Groups: ['A', 'B']
  1. Для первой оценки 8 ключа ещё нет. get(8, 0) даёт 0, прибавление даёт 1, присваивание создаёт запись 8: 1.
  2. Первое появление 10 создаёт 10: 1. Оценка 12 создаёт 12: 1.
  3. Второе появление 10 читает существующий счётчик 1 и заменяет его на 2.
  4. unique_groups оставляет названия A и B без повторений. sorted() превращает их в упорядоченный список для стабильного вывода.

students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
backup = students
backup["s02"] = {"name": "Mia", "group": "B", "scores": []}
backup["s01"]["scores"].append(12)
print(list(students))
print(students["s01"]["scores"])
Консоль
['s01', 's02']
[8, 10, 12]

Добавление внешнего ключа и изменение вложенного списка видны через students. backup не является запасной версией: это другое имя того же словаря.

Сделаем поверхностную копию.

Поверхностная копия: внешний словарь отдельно
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
backup = students.copy()
backup["s02"] = {"name": "Mia", "group": "B", "scores": []}
backup["s01"]["group"] = "B"
backup["s01"]["scores"].append(12)
print("Original IDs:", list(students))
print("Shared record:", students["s01"])
backup["s01"] = {"name": "Sam", "group": "C", "scores": []}
print("Original:", students["s01"])
print("Replacement:", backup["s01"])
Консоль
Original IDs: ['s01']
Shared record: {'name': 'Alex', 'group': 'B', 'scores': [8, 10, 12]}
Original: {'name': 'Alex', 'group': 'B', 'scores': [8, 10, 12]}
Replacement: {'name': 'Sam', 'group': 'C', 'scores': []}
  1. copy() создаёт новый внешний словарь, поэтому s02 добавился только в backup.
  2. Существующая запись s01 пока общая: изменение group и append() видно в оригинале.
  3. Присваивание backup["s01"] = ... заменяет ссылку только внутри backup. Теперь этот путь ведёт к новой записи Sam.
  4. Оригинал продолжает ссылаться на Alex. Уже сделанные изменения B и [8, 10, 12] не отменяются.

Если нужна полная копия, то можно воспользоваться deepcopy.

Глубокая копия учебных данных
from copy import deepcopy

students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
backup = deepcopy(students)
backup["s01"]["group"] = "B"
backup["s01"]["scores"].append(12)
print("Original:", students["s01"])
print("Copy:", backup["s01"])
Консоль
Original: {'name': 'Alex', 'group': 'A', 'scores': [8, 10]}
Copy: {'name': 'Alex', 'group': 'B', 'scores': [8, 10, 12]}

Строка from copy import deepcopy делает доступным готовый инструмент deepcopy из стандартного модуля copy. Для рассматриваемых словарей, списков, строк и чисел он создаёт независимую вложенную копию.

17 / Самопроверка

Вопрос

Что выведет преобразование?

Длина после преобразования
scores = [8, 8, 10]
result = list(set(scores))
print(len(result))
Выберите результат.

set убрал повторный элемент 8, поэтому в списке осталось два элемента.

Длина исходного списка была 3, но повторение потеряно при создании множества.

Целые числа хешируемы и могут быть элементами множества.

Вопрос

Как устроены данные?

Группы и ID
groups = {"A": ["s01", "s02"]}
Выберите верные описания этой структуры.

Ключ A выбирает список студентов группы.

Внутри квадратных скобок находятся строковые ID.

У этого значения нет полей name или scores; это список строк.

Вопрос

Какой путь ведёт ко второй оценке?

Выберите путь
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
Нужно получить число 10. Выберите подходящее выражение.

Два ключа выбирают список, индекс 1 выбирает вторую оценку.

Во внешнем словаре нет ключа scores; сначала нужен ID.

У списка из двух элементов допустимы индексы 0 и 1. Индекс 2 вызовет IndexError.

Вопрос

На каком шаге возникнет ошибка?

Ошибка в конце пути
students = {"s01": {"name": "Alex", "group": "A", "scores": []}}
print(students["s01"]["scores"][0])
Выберите точное объяснение.

Ключ s01 существует и даёт внутренний словарь.

Поле scores существует и содержит пустой список.

Пустой список не содержит ни одной позиции. Первые два шага успешны.

Вопрос

Что вернёт get?

Пустой список и значение по умолчанию
student = {"scores": []}
print(student.get("scores", [12]))
Выберите ожидаемый вывод.

Ключ существует. get() возвращает записанный пустой список и не использует значение по умолчанию.

Значение по умолчанию использовалось бы только при отсутствии ключа scores.

По ключу scores записан список, а не None.

Вопрос

Как изменить группу и сохранить остальные поля?

Запись перед изменением
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
Студент s01 существует. Выберите операцию, которая сохранит его имя и оценки.

Меняется только поле внутренней записи.

Вся запись заменится неполным словарём, name и scores исчезнут из неё.

Имя students начнёт указывать на новый журнал. В нём нет остальных полей и прежних студентов.

Вопрос

Что выведет вложенный цикл?

Два уровня перебора
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
    "s02": {"name": "Mia", "group": "B", "scores": []},
}
for student_id, student in students.items():
    for score in student["scores"]:
        print(student_id, score)
Выберите последовательность строк.

У s01 две оценки. У s02 список пустой, поэтому внутренний цикл для него не делает ни одного шага.

Внешний студент не меняется после каждой отдельной оценки. Сначала завершается его внутренний цикл.

Так выглядел бы вывод списков без внутреннего цикла; здесь score является отдельной оценкой.

Вопрос

Что получилось после группировки?

Проверьте группировку
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
    "s02": {"name": "Mia", "group": "A", "scores": [12]},
    "s03": {"name": "Alex", "group": "B", "scores": []},
}
groups = {}
for student_id, student in students.items():
    groups.setdefault(student["group"], []).append(student_id)
print(groups)
Выберите точный результат.

Для каждой новой группы setdefault создал свой список, для существующей вернул прежний.

setdefault не заменяет существующее значение A пустым списком.

В каждой новой группе создаётся отдельный список; общего шаблона здесь нет.

Вопрос

Что изменит поверхностная копия?

Изменение через копию
students = {
    "s01": {"name": "Alex", "group": "A", "scores": [8, 10]},
}
backup = students.copy()
backup["s01"]["scores"].append(12)
print(students["s01"]["scores"])
Выберите вывод.

copy() отделил внешний словарь, но запись и вложенный список остались общими.

Такой результат был бы у независимой глубокой копии, но здесь копия поверхностная.

ID s01 и поле scores есть и в оригинале, и в копии.
